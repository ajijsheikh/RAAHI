## 1. Core Tables (Postgres + PostGIS)

### 1.1 `trips`
| Column | Type | Notes |
|---|---|---|
| `id` | UUID | Primary key, generated by app |
| `user_id` | UUID | Client-generated, stored via `flutter_secure_storage` |
| `status` | ENUM ('planning', 'active', 'completed', 'cancelled') | Default 'planning' |
| `query_text` | TEXT | Raw user input, for audit/logging |
| `max_budget_inr` | INTEGER | Hard budget ceiling |
| `target_eta` | TIMESTAMPTZ | User's target arrival time |
| `emergency_contact_phone` | TEXT | E.164 format, validated at API boundary |
| `created_at` | TIMESTAMPTZ | Default now() |
| `completed_at` | TIMESTAMPTZ | Null until trip ends |

### 1.2 `itinerary_legs`
| Column | Type | Notes |
|---|---|---|
| `id` | UUID | PK |
| `trip_id` | UUID | FK → trips.id |
| `leg_index` | INTEGER | Order within the trip (1, 2, 3…) |
| `mode` | TEXT | 'walk', 'bus', 'metro', 'train', 'auto', 'rideshare' |
| `from_name` | TEXT | Displayable origin label |
| `to_name` | TEXT | Displayable destination label |
| `scheduled_departure` | TIMESTAMPTZ |
| `actual_arrival` | TIMESTAMPTZ | Null until leg completes |
| `cost_inr` | INTEGER | Actual cost paid/estimated |
| `status` | ENUM ('planned', 'active', 'completed', 'superseded') | Default 'planned' |

### 1.3 `trip_events`
| Column | Type | Notes |
|---|---|---|
| `id` | UUID | PK |
| `trip_id` | UUID | FK → trips.id |
| `event_type` | TEXT | 'replan', 'alert', 'budget_violation' |
| `trigger_reason` | TEXT | 'delay', 'unsafe_zone', 'budget_ceiling' |
| `leg_index` | INTEGER | Null for alert/budget; populated for replan |
| `old_leg` | JSONB | The leg being replaced (for replan events) |
| `new_leg` | JSONB | The replacement leg (for replan events) |
| `message` | TEXT | Human-readable display message |
| `twilio_sid` | TEXT | Null unless safety trigger fired |
| `created_at` | TIMESTAMPTZ | Default now() — drives SSE stream |

### 1.4 `safety_zones`
| Column | Type | Notes |
|---|---|---|
| `id` | UUID | PK |
| `zone_name` | TEXT | Human-readable, e.g. "Railway Colony Slum" |
| `geom` | GEOMETRY(Polygon, 4326) | PostGIS polygon defining the flagged zone |
| `source` | TEXT | How this zone was seeded — e.g. "demo_manual", "citizen_report" |
| `confidence` | REAL | 0.0–1.0, how reliable this zone flag is |
| `created_at` | TIMESTAMPTZ | Default now() |

### 1.5 `amenities`
| Column | Type | Notes |
|---|---|---|
| `id` | UUID | PK |
| `name` | TEXT | Display name, e.g. "Express Meal Center" |
| `category` | TEXT | 'budget_food' | 'budget_stay' |
| `price_inr` | INTEGER | Price for the budget option |
| `distance_km` | REAL | Distance from some reference (destination or user position) |
| `geom` | GEOMETRY(Point, 4326) | PostGIS point for radius searches |
| `description` | TEXT | One-line description for UI list |
| `source` | TEXT | "demo_curated" for hackathon scope |

## 2. Key Spatial Queries Used by the Agent Layer

### 2.1 Point-in-Zone (Safety Watcher)
```sql
SELECT zone_name, confidence
FROM safety_zones
WHERE ST_Contains(geom, ST_SetSRID(ST_MakePoint(:lng, :lat), 4326));
```
Returns all flagged zones containing the user's current position.

### 2.2 Radius Search (Amenity Discovery)
```sql
SELECT name, category, price_inr, distance_km, ST_Distance(
  geom, ST_SetSRID(ST_MakePoint(:lng, :lat), 4326)
) / 1000 AS computed_dist_km
FROM amenities
WHERE ST_DWithin(geom, ST_SetSRID(ST_MakePoint(:lng, :lat), 4326), :radius_m)
ORDER BY computed_dist_km ASC
LIMIT 5;
```
Finds amenities within ~2 km of the user's position or destination.

### 2.3 Itinerary Cost Total
```sql
SELECT SUM(cost_inr) AS total_cost, COUNT(*) AS leg_count
FROM itinerary_legs
WHERE trip_id = :trip_id AND status != 'cancelled';
```

## 4. Indexes (for demo performance)

- `gist(safety_zones.geom)` — for point-in-zone queries
- `gist(amenities.geom)` — for radius searches
- `idx_itinerary_trip_id` on `itinerary_legs(trip_id, leg_index)` — leg ordering
- `idx_trip_events_trip_id` on `trip_events(trip_id, created_at)` — SSE streaming order

## 5. Data seeding for the Hackathon

Seeding scripts live in `infra/sql/` and are run once at docker-compose startup. They populate:
- 2–3 complete trip routes with full itineraries
- 3–5 safety zones around plausible walk/transit paths
- 6–10 amenities (budget food + stay) near the demo destination
- 3 predefined trips with different budgets/ETA combinations

These scripts are the **only** source of truth for the demo — no live API data is fetched at runtime.
